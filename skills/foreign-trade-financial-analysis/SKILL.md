# 外贸财务分析

执行一条固定、证据可追溯的分析链路。先核对数据和口径，再计算和解释；不得用猜测补齐财务事实。

## 必读参考

- 开始分析前读取 [references/data-contract.md](references/data-contract.md)，建立字段映射、主键和币种口径。
- 需要计算指标或判断异常时读取 [references/metrics-and-rules.md](references/metrics-and-rules.md)。
- 生成交付物前读取 [references/output-contract.md](references/output-contract.md)。

## 固定工作流

严格按下列阶段执行。任一阻断性校验失败时停止进入后续阶段，输出待确认清单，不生成确定性结论。

### 1. 定义分析任务

1. 确认分析期间、基准期间、报告币种、汇率口径、含税/未税口径和时区。
2. 确认分析维度：客户、国家/地区、订单、SKU、产品线、业务员、渠道、贸易术语或上述组合。
3. 确认交付物与用途，区分经营复盘、管理预测、税务或审计支持。
4. 未指定时采用：月度分析、上月环比、去年同期同比、报告币种 CNY；把这些标为“待确认假设”，不得冒充企业正式口径。

### 2. 盘点与保护数据

1. 仅在用户授权范围内读取文件和数据源；优先本地处理。
2. 列出每个数据源、期间、行数、字段、更新时间和来源文件。
3. 不在输出中暴露密钥、完整银行账号、身份证件、私人联系方式等敏感信息。
4. 不修改原始文件。将中间结果和交付物写入独立输出目录。

### 3. 建立字段映射与关联键

1. 按数据契约将源字段映射为标准字段。
2. 优先用业务主键关联：`order_id`、`invoice_id`、`receipt_id`、`shipment_id`；不得仅按客户名或金额模糊拼接。
3. 将无法唯一关联、多对多关系和重复主键列入异常清单。
4. 为每笔金额保留原币金额、币种、汇率、汇率日期/版本和折算金额。

### 4. 清洗与质量门禁

1. 统一日期、币种代码、客户/SKU 标识、科目名称、正负号和小数精度。
2. 检查缺失值、重复记录、跨期记录、非法币种、异常汇率和金额不平衡。
3. 输出数据质量报告，包含通过项、警告项、阻断项及受影响金额。
4. 出现以下任一情况必须停止确定性分析：报告币种未知；汇率来源或日期未知且包含多币种；关键金额字段缺失；关键主键重复导致无法去重；收入/成本确认口径冲突。

### 5. 多表对账

依次执行并保留差异明细：

1. 订单 ↔ 出货：数量、SKU、出货日期和贸易术语。
2. 出货/订单 ↔ 发票：开票金额、币种、税额和未开票余额。
3. 发票 ↔ 收款 ↔ 银行流水：到账金额、手续费、短款、未核销和重复收款。
4. 成本/费用 ↔ 订单或期间：采购、运费、保险、关税、平台费、佣金和其他可归属费用。
5. 对账不平时将差异标为 `pending_confirmation`，不得强行摊平。

### 6. 计算核心指标

按参考定义计算并展示分子、分母、公式和数据来源：

1. 收入、销售成本、毛利、毛利率及同比/环比。
2. 客户、国家、SKU、产品线和订单的毛利贡献与排名。
3. 费用、费用率、预算偏差，区分固定费用与可变费用。
4. 应收余额、账龄分桶、逾期率、DSO、回款率和客户集中度。
5. 原币与报告币口径的汇兑影响；实际汇兑损益与估算影响必须分开。
6. 经营、投资、筹资现金流和净现金变化（数据支持时）。

### 7. 解释变化并检测异常

1. 用可验证分解解释毛利率变化：价格、销量、产品组合、采购成本、物流关税、折扣和汇率。
2. 同时使用规则阈值和历史分布识别异常；阈值默认只作候选，不直接判定舞弊或错误。
3. 每个结论附证据：指标值、对比值、差异、来源表和筛选范围。
4. 将“已证实事实”“基于数据的推断”“待业务确认”分栏呈现。

### 8. 现金流情景预测

仅在数据足够时执行：

1. 至少使用 12 个月历史数据识别季节性；不足时只做滚动收支计划，不宣称统计预测。
2. 建立乐观、中性、悲观三种场景，显式列出回款天数、订单增长、毛利率、汇率和付款节奏假设。
3. 标出预计现金缺口时间、峰值缺口和主要驱动因素。
4. 预测只辅助决策，不作为贷款、报税、审计或付款的自动依据。

### 9. 生成并复核交付物

1. 按输出契约生成数据质量报告、对账差异、指标表、图表、管理层摘要和待确认清单。
2. 所有关键表注明币种、单位、期间、含税口径和数据截止时间。
3. 复算总计与分组汇总，确认图表数值和底表一致。
4. 给出 2–3 条行动建议；每条说明证据、责任角色、建议时点和风险，不自动执行付款、催收、报税或会计记账。
5. 明确要求财务负责人复核，涉及税务、审计、授信或对外披露时必须由有权限人员签字确认。

## 执行原则

- 使用 Python 或等价可复现方式完成复杂计算，保留公式、查询、参数和运行日志。
- 金额计算使用定点小数或数据库 `DECIMAL`，不得使用二进制浮点直接汇总财务金额。
- 查询数据库时只读、参数化、限制范围；不要让模型生成并执行任意写 SQL。
- 不编造缺失的汇率、成本、付款日期、预算或会计科目。
- 数据变化后从清洗和对账阶段重新运行，不沿用旧结论。
- 网页案例仅提供流程启发，不构成会计准则、税务或审计意见。
